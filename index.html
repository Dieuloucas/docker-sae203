ShareBox

Serveur de partage de fichiers sécurisé — containerisé avec Docker

Python 3 Flask SQLite HTML/CSS Docker debian:latest Git

SAE 2.03 — IUT du Havre — BUT Informatique S2

Le Projet

Serveur web local permettant à des utilisateurs authentifiés de partager des fichiers. L'administrateur gère les comptes depuis une interface dédiée.

🔐

Authentification

Page de login avec vérification en base SQLite. La session Flask retient l'utilisateur connecté entre les requêtes.

📁

Partage de fichiers

Upload via formulaire HTML (POST). Téléchargement en un clic (GET). Fichiers stockés dans uploads/ du conteneur.

⚙️

Espace admin

Créer des comptes (user ou admin), voir tous les comptes existants.

🐳

Containerisé

docker build installe tout et initialise la BDD. docker run lance le serveur.

📦 Image

docker build — Debian + Python + Flask + code + BDD initialisée. Statique.

🏃 Conteneur

docker run — l'image en cours d'exécution. Isolé, accessible via le port mappé.

La Base de Données — SQLite

SQLite stocke toute la BDD dans un seul fichier. Python l'intègre nativement. Pas de serveur séparé à installer.

📄 JSON (option rejetée)

Fichier texte simple. Pas de requêtes, pas de types, risque de corruption.

🗄️ SQLite (choix retenu)

Vraie BDD relationnelle. Requêtes SQL. Intégrité garantie. Intégré à Python.

La table utilisateurs

TABLE utilisateurs ┌──────────────────────────────────────────────┐ │ id INTEGER PRIMARY KEY AUTOINCREMENT │ │ nom TEXT NOT NULL UNIQUE │ │ mdp TEXT NOT NULL │ │ role TEXT NOT NULL │ └──────────────────────────────────────────────┘ Données initiales (créées par init_db.py) : id=1 nom="admin" mdp="admin123" role="admin" id=2 nom="alice" mdp="alice123" role="user"
INTEGER PRIMARY KEY AUTOINCREMENT

L'id est généré automatiquement à chaque INSERT. On ne le spécifie jamais manuellement.

TEXT NOT NULL UNIQUE

nom est obligatoire et unique. Si on insère un doublon, SQLite lève une IntegrityError — capturée en Python pour afficher un message propre.

conn.row_factory = sqlite3.Row

Permet d'accéder aux colonnes par nom (row["nom"]) plutôt que par index (row[0]). Rend le code plus lisible.

conn.commit()

Valide les modifications. Sans commit(), un INSERT ou UPDATE n'est pas sauvegardé de façon permanente.

Les 4 requêtes SQL du projet

-- init_db.py : créer la table CREATE TABLE IF NOT EXISTS utilisateurs ( id INTEGER PRIMARY KEY AUTOINCREMENT, nom TEXT NOT NULL UNIQUE, mdp TEXT NOT NULL, role TEXT NOT NULL ); -- database.py : vérifier les identifiants (login) SELECT * FROM utilisateurs WHERE nom = ? AND mdp = ?; -- database.py : créer un compte (admin) INSERT INTO utilisateurs (nom, mdp, role) VALUES (?, ?, ?); -- database.py : lister tous les comptes SELECT id, nom, role FROM utilisateurs;
CREATE TABLE IF NOT EXISTS

Crée la table seulement si elle n'existe pas. Permet de relancer le script sans erreur.

? (paramètres liés)

Les ? sont des placeholders. SQLite les remplace par les valeurs du tuple passé en 2ème argument. Empêche les injections SQL — on ne concatène jamais des variables dans du SQL.

INSERT OR IGNORE

Dans init_db.py, si le compte admin existe déjà (relancement), SQLite ignore l'INSERT sans erreur.

Le Code Python — server.py & database.py

Deux fichiers Python avec un rôle chacun. database.py parle à SQLite. server.py gère les routes HTTP.

database.py

Les 4 fonctions

import sqlite3 DB_PATH = "sharebox.db" def get_connection(): conn = sqlite3.connect(DB_PATH) conn.row_factory = sqlite3.Row return conn def verifier_connexion(nom, mdp): conn = get_connection() curseur = conn.cursor() curseur.execute( "SELECT * FROM utilisateurs WHERE nom = ? AND mdp = ?", (nom, mdp) ) utilisateur = curseur.fetchone() conn.close() return utilisateur def creer_compte(nom, mdp, role): conn = get_connection() curseur = conn.cursor() try: curseur.execute( "INSERT INTO utilisateurs (nom, mdp, role) VALUES (?, ?, ?)", (nom, mdp, role) ) conn.commit() conn.close() return True except sqlite3.IntegrityError: conn.close() return False def lister_comptes(): conn = get_connection() curseur = conn.cursor() curseur.execute("SELECT id, nom, role FROM utilisateurs") comptes = curseur.fetchall() conn.close() return comptes
sqlite3.connect(DB_PATH)

Ouvre une connexion au fichier sharebox.db. Crée le fichier s'il n'existe pas.

curseur.fetchone()

Récupère la 1ère ligne du résultat. Retourne None si rien ne correspond — ce qui permet if utilisateur: dans server.py.

try / except IntegrityError

Si le nom est déjà pris (UNIQUE), SQLite lève cette exception. On la capture pour retourner False au lieu de planter.

conn.close()

Ferme la connexion après usage pour libérer les ressources.

server.py — 5 routes

Route 1 — Login GET/POST /

@app.route("/", methods=["GET", "POST"]) def login(): erreur = None if request.method == "POST": nom = request.form["nom"] mdp = request.form["mdp"] utilisateur = verifier_connexion(nom, mdp) if utilisateur: session["utilisateur"] = utilisateur["nom"] session["role"] = utilisateur["role"] return redirect("/fichiers") else: erreur = "Nom ou mot de passe incorrect." return render_template("login.html", erreur=erreur)
methods=["GET", "POST"]

GET = afficher le formulaire vide. POST = traiter la soumission. Sans methods, Flask n'accepte que GET.

verifier_connexion(nom, mdp)

Appelle database.py qui fait le SELECT SQL. server.py ne contient aucun SQL.

session["utilisateur"] = ...

Flask stocke ça dans un cookie chiffré. Chaque requête suivante contient ce cookie — c'est ainsi que le serveur sait qui est connecté.

Route 2 — Fichiers GET /fichiers

@app.route("/fichiers") def fichiers(): if "utilisateur" not in session: return redirect("/") liste = os.listdir(UPLOAD_FOLDER) return render_template("index.html", fichiers=liste, utilisateur=session["utilisateur"], role=session["role"])
if "utilisateur" not in session

Protection de route. Pas de session = pas connecté = retour au login.

render_template("index.html", fichiers=liste, ...)

Passe les variables Python au template. fichiers devient {{ fichiers }} en HTML, etc.

Route 3 — Upload POST /upload

@app.route("/upload", methods=["POST"]) def upload(): if "utilisateur" not in session: return redirect("/") fichier = request.files["fichier"] if fichier.filename != "": chemin = os.path.join(UPLOAD_FOLDER, fichier.filename) fichier.save(chemin) return redirect("/fichiers")
request.files["fichier"]

Récupère le fichier du formulaire. Différent de request.form (texte). Nécessite enctype="multipart/form-data" sur le <form> HTML.

fichier.save(chemin)

Sauvegarde le fichier sur le disque du conteneur.

Route 4 — Download GET /download/<nom>

@app.route("/download/<nom>") def download(nom): if "utilisateur" not in session: return redirect("/") return send_from_directory(UPLOAD_FOLDER, nom, as_attachment=True)
<nom> dans l'URL

Paramètre dynamique. /download/rapport.pdf → nom = "rapport.pdf".

as_attachment=True

Force le téléchargement au lieu d'afficher le fichier dans le navigateur.

Route 5 — Admin GET/POST /admin

@app.route("/admin", methods=["GET", "POST"]) def admin(): if session.get("role") != "admin": return redirect("/") message = None if request.method == "POST": succes = creer_compte( request.form["nom"], request.form["mdp"], request.form["role"] ) message = (f"Compte '{request.form['nom']}' créé." if succes else "Ce nom est déjà pris.") comptes = lister_comptes() return render_template("admin.html", message=message, comptes=comptes)
session.get("role") != "admin"

Double protection — get() retourne None si la clé n'existe pas. Si le rôle n'est pas admin, on redirige.

creer_compte(...)

Retourne True ou False — server.py choisit le message selon le résultat.

Le Code HTML — Templates Jinja2

Flask utilise Jinja2 pour injecter du Python dans le HTML. Les {{ }} affichent des variables. Les {% %} font de la logique.

<!-- Variable Python → HTML --> <span>👤 {{ utilisateur }}</span> <!-- Condition : affiché seulement si erreur n'est pas None --> {% if erreur %} <div class="erreur">{{ erreur }}</div> {% endif %} <!-- Boucle sur la liste "fichiers" de os.listdir() --> {% for f in fichiers %} <div class="fichier-item"> <span>📄 {{ f }}</span> <a href="/download/{{ f }}">⬇ Télécharger</a> </div> {% endfor %} <!-- Visible seulement si admin --> {% if role == "admin" %} <a href="/admin">⚙ Gérer les comptes</a> {% endif %} <!-- Boucle sur les comptes retournés par lister_comptes() --> {% for compte in comptes %} <tr> <td>{{ compte["id"] }}</td> <td>{{ compte["nom"] }}</td> <td>{{ compte["role"] }}</td> </tr> {% endfor %}
{{ variable }}

Jinja2 remplace par la valeur Python envoyée via render_template(). None → rien affiché.

{% if %} / {% endif %}

HTML conditionnel. Généré côté serveur avant envoi au navigateur.

{% for f in fichiers %}

Génère un bloc HTML par élément de la liste.

enctype="multipart/form-data"

Attribut obligatoire sur le <form> qui envoie un fichier. Sans lui, request.files est vide côté Flask.

Le Dockerfile — Instruction par instruction

Le Dockerfile est une recette. Docker l'exécute de haut en bas lors du docker build.

FROM debian:latest RUN apt-get update && apt-get install -y \ python3 \ python3-pip \ && rm -rf /var/lib/apt/lists/* WORKDIR /app COPY app/ . RUN pip3 install --break-system-packages -r requirements.txt RUN python3 init_db.py EXPOSE 5000 CMD ["python3", "server.py"]
InstructionCe qu'elle fait
FROM debian:latestImage de base Linux Debian vierge
RUN apt-get updateMet à jour la liste des paquets
apt-get install python3 python3-pipInstalle Python et pip
rm -rf /var/lib/apt/lists/*Supprime les caches — réduit la taille
WORKDIR /appCrée et définit /app comme dossier de travail
COPY app/ .Copie tout le code dans /app du conteneur
pip3 install -r requirements.txtInstalle Flask
python3 init_db.pyCrée sharebox.db avec les comptes par défaut
EXPOSE 5000Documente le port (nécessaire pour -p)
CMD ["python3", "server.py"]Lance le serveur au démarrage

Configurer SSH

# 1. Générer les clés SSH (Entrée × 3 pour les valeurs par défaut) ssh-keygen -t ed25519 -C "ton.email@etudiant.univ-lehavre.fr" # 2. Afficher la clé publique à copier sur GitHub cat ~/.ssh/id_ed25519.pub # 3. Tester la connexion ssh -T git@github.com # Réponse : Hi USERNAME! You've successfully authenticated...
Pourquoi SSH ?

Push sans mot de passe à chaque fois. La clé privée reste sur ta machine, la clé publique est sur GitHub.

Ajouter la clé

GitHub → icône profil → Settings → SSH and GPG keys → New SSH key → coller id_ed25519.pub → Save.

Privée vs publique

id_ed25519 = privée (jamais partager). id_ed25519.pub = publique (déposée sur GitHub).
